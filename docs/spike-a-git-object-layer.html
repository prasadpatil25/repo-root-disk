Spike A

Git Object Layer

Proves the write path for Repo as Root Disk: putBlob, putTree, putCommit, casRef driven from a plain page with no server, then measures where GitHub's limits actually trip. No VM involved. The numbers this produces are the spine of the rate-limit budget.

Point this at a throwaway repository. Every experiment writes real git objects and consumes your account's content-generating budget, which is 500 writes per hour and shared across everything you do on GitHub. Runs are capped and stoppable, but nothing here is undoable except by deleting the repo.

Experiments

Each run appends to the log below. Run E2 before E4, which needs a commit to read back.

E1

Blob size sweep

POST blobs at 64 KB, 256 KB, 1 MB and 4 MB. Gives latency against payload size, which is what decides the chunk size in the design. Two warm-up writes are discarded first, and sizes are interleaved rather than grouped, so connection setup cost does not land entirely on whichever size runs first.

writes: 12
E2

Commit cycle

Full blobs, tree, commit, ref update. Compares chunk-exploded against a single delta pack of the same total size, so the N+3 versus 4 request model gets checked end to end.

writes: 22
E3

Secondary limit probe

Small blobs back to back until a 403 or 429 arrives, recording the exact request index and elapsed time. This is the measurement that confirms or refutes 80 per minute and 500 per hour.

Run this last. Tripping the limit throttles the whole account for the rest of the hour and poisons every measurement that follows it.

writes: up to 100
E4

Read path

Same content through three routes: the blobs API, raw.githubusercontent.com, and a ranged request. Answers whether the boot path can stay off the API entirely, and whether it works at all on a private repo.

This page is open as a file:// URL, so its origin is null. The API tolerates that, but the CDN may reject it outright, which looks identical to a real CORS failure. Serve this page over http before trusting an E4 result.

Self-contained: if no commit exists in this session it creates a minimal one first. A 404 from jsDelivr moments after a commit may be CDN propagation rather than a CORS or visibility problem, so re-run it if that is the only failure.

writes: 0, or 4 if it must bootstrap
E7

Boot path read benchmark

Writes n chunks, then reads them all back through GET /git/blobs/:sha at concurrency. This is the fallback read path on a public repo and the only read path on a private one, since the CDN refuses an Authorization preflight. Reports both directions and the read throughput a cold boot would see.

writes: 16, then equal reads
E6

Concurrency ramp

The same batch uploaded at rising concurrency, to find the operating point for P5. Serial round trips cap a client near 145 writes per minute, so parallelism is the only way to reach, or trip, the real secondary ceiling. GitHub permits 100 concurrent requests.

writes: 80
E5

Compare and swap

Updates the ref with a stale parent and force: false. Expects a rejection, which is the concurrency primitive the sync protocol depends on in P7.

writes: 1 attempt
