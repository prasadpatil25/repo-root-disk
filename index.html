Repo as Root Disk

A browser-native Linux VM whose disk is committed into a git repository.

Browser-native virtual machines all treat remote storage as read only: a disk image is streamed in, writes land in browser-local storage, and nothing is ever written back. Machine state is therefore trapped in one browser profile on one device, and clearing site data destroys it.

This closes that loop. The guest's dirty block set is committed into an ordinary code hosting service as git objects, so a machine's state becomes a commit and its history becomes a git history. A machine can be rebuilt on any device from a reference alone. There is no server: a static page, your repository, and your browser.

What you will need

A fine-grained access token scoped to a single repository you do not mind filling with machine state. The token stays in your browser and is sent only to the host's API; nothing else receives it, because there is nothing else.

This page is the artifact for a research paper. The measurement harnesses in the repository write real commits and consume real rate limit, so read the README before running them.

What is measured

  • Restore cost is the live set plus three requests, and does not grow with a machine's age.
  • Deduplication is exactly the reciprocal of disk occupancy, so it is worth nothing on a full disk.
  • The published rate limits are not the enforced ones.
  • The low-level object API this is built on exists on one of three hosts surveyed; against a batch-commit host the same sync costs twenty times fewer requests and thirteen times less time.

Reproducing it

Three of the paper's central claims need no credentials at all: node src/analysis/restore-scaling.mjs, node src/analysis/report.mjs traces/mke2fs-256mb.json, and the 618 tests. The README maps each claim to the command that produces it.
